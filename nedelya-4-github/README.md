# Урок 4. GitHub с нуля: как пользоваться и не бояться

*Интенсив клуба НейроРенессанс · Нейроспринт · неделя 4 · тема выбрана голосованием · эфир 27.10 · сдать до воскресенья 01.11, 23:59 (МСК)*

**Цель одной фразой:** в команде Гермеса появляется сотрудник **Архивариус**, который складывает твою работу в закрытый сейф на GitHub, возвращает вчерашнюю версию сломанного файла, читает чужие скиллы до установки и помогает отдать своё людям — когда ты сам этого захочешь.

**GitHub — это не «для программистов».** Это сейф с историей. Он помнит все версии твоих документов: сломал файл — вернул вчерашний, умер диск — скачал из сейфа, захотел поделиться — дал ссылку. Слово «репозиторий» тебе дальше не понадобится ни разу: мы говорим «хранилище».

**Весь урок — разговор словами + сайт GitHub глазами.** Ты копируешь готовые фразы в чат Гермеса, Архивариус делает работу, а на сайте GitHub ты своими глазами проверяешь, что файлы на месте и история есть. Терминал нужен дважды и ненадолго: на входе в GitHub и на раскладке скиллов сотрудника — вместе минут десять. Всё остальное для тех, кто любит команды, — в необязательном блоке [для технарей](#для-технарей-и-тех-кто-любит-читать) в конце.

Главное правило недели: **сломать безопасно, если ты сохранился.** Весь страх перед GitHub — это страх необратимости. А GitHub как раз и есть машина, которая делает любое действие обратимым.

## Что подготовить

| Что | Зачем | Где взять |
|---|---|---|
| **Почта, к которой у тебя есть доступ прямо сейчас** | GitHub пришлёт на неё код подтверждения при регистрации | любая твоя рабочая почта |
| **Телефон или второе окно браузера** | на уроке ты впишешь короткий код на странице входа GitHub — как делал с Nous Portal на уроке 0 | уже есть |
| **Сервер с Гермесом работает**, чат отвечает | весь урок идёт словами через Гермеса | вкладка Chat, проверь одной фразой «ответь одним словом: живой» |
| **Папка с твоей работой** за недели 0–3: точка А, портрет клиента, оффер, разборы роликов | это то, что мы положим в сейф | обычно `~/razbor-biznesa` |
| **Придуманное имя пользователя** для GitHub | оно будет видно во всех твоих ссылках | пусть будет человеческое: `anna-nutricio`, а не `qwerty1988` |
| Если есть аккаунт GitHub — **вспомни логин и пароль** | войдёшь быстрее всех | менеджер паролей / почта |

Аккаунт можно **не** заводить заранее: регистрация занимает 3–5 минут и выписана по пунктам в [шаге 0а](#0а-регистрация-35-минут-бегло). Но если успеешь до урока — сэкономишь время и спокойно пойдёшь со всеми дальше.

> **Чего не нужно готовить вообще:** никаких ключей, токенов, SSH, «настройки окружения». Один вход по коду — и дальше словами.

## Зачем это тебе: четыре вещи

Не «потому что так принято у разработчиков», а по-честному, четыре практические причины.

**1. Сейф.** Твоя работа за четыре недели — точка А, портрет клиента, оффер, разборы роликов, свои скиллы — лежит сейчас в одном месте: на одном сервере, в одной папке. Диск умрёт, Гермес перепишет файл, ты удалишь не то — и работы нет. Сейф на GitHub живёт отдельно от твоего сервера.

**2. Откат — то, ради чего GitHub вообще придумали.** Это не бэкап папки целиком. Это **машина времени для каждого файла по отдельности.** Переписал оффер и стало хуже? «Верни вчерашнюю версию 03-offer.md» — и она вернулась, а остальные файлы не тронуты. Именно это снимает главный страх: **сломать безопасно, если ты сохранился.**

**3. Взять чужое.** Почти все скиллы, агенты и готовые инструкции для Гермеса живут на GitHub. Умеешь прочитать чужую страницу — берёшь работающее решение за 5 минут вместо вечера своей писанины. Не умеешь — ставишь вслепую то, что тебе прислали в чате.

**4. Отдать своё.** Когда ты хочешь раздать свой скилл клубу, клиентам или студентам — нужна одна ссылка, по которой человек всё поймёт и поставит сам. Это и есть публичное хранилище с нормальным README. Без него твоя работа существует только у тебя на сервере.

Порядок на уроке строго такой: **СОХРАНИТЬ своё → ОТКАТ → ВЗЯТЬ чужое → ОТДАТЬ своё.** Пока своё не сохранено, остальное подождёт.

## GitHub за 10 минут: куда ты вообще попал

Прежде чем что-то делать руками — пять минут про то, что это за место. Без этого все шаги ниже выглядят как магия.

### Это склад файлов, который помнит всё

Представь **Яндекс.Диск, который помнит каждую версию каждого документа.** Вот и всё, это GitHub.

Разница с обычным облаком ровно одна, и она главная:

| Облако (Яндекс.Диск, Google Drive) | GitHub |
|---|---|
| хранит **последнюю** версию файла | хранит **все** версии |
| перезаписал файл — прошлого больше нет | перезаписал файл — прошлый лежит рядом, с датой |
| «кто это поменял?» — обычно не узнать | видно, кто менял, когда и что именно |
| двое правят один файл → кто сохранил последним, тот и прав | двое правят один файл → GitHub не даёт молча затереть чужие правки |

Поэтому про GitHub и говорят «машина времени». Не «папка в интернете», а **папка с историей.**

### Словарь: семь слов, и больше не надо

Все страшные слова этого мира сводятся к семи. Выучивать не надо — просто знай, что они значат, когда увидишь их на сайте.

| Слово, которое ты увидишь | Что это по-человечески |
|---|---|
| **репозиторий** (repository, repo) | папка проекта. Мы в уроке говорим «хранилище» |
| **коммит** (commit) | точка сохранения. Как в игре: сохранился — можно вернуться |
| **история** (history, commits) | все твои точки сохранения по датам |
| **README** | витрина. Текст, который человек видит первым, открыв твоё хранилище |
| **приватный / публичный** (private / public) | закрыто только для тебя / открыто всему интернету |
| **клон** (clone) | копия хранилища себе на компьютер или сервер |
| **звезда / форк** (star / fork) | «лайк» и «взял себе копию, буду переделывать под себя» |

Дальше по уроку эти слова почти не понадобятся: Архивариус говорит с тобой по-русски — «точка сохранения», «вчерашняя версия», «это уйдёт в интернет, это нет».

### Что там лежит у людей на самом деле

Главное заблуждение: «GitHub — это для кода». Код там действительно есть. Но рядом с ним лежит всё остальное, что живёт текстом:

- документы, инструкции, конспекты, гайды;
- промпты и **скиллы для агентов** — те самые, которые ты ставил на уроке 2;
- шаблоны, чек-листы, контент-планы;
- целые курсы.

**Живой пример у тебя уже есть.** Весь этот интенсив — уроки, которые ты читаешь, и скиллы, которые ставит Гермес, — лежит на GitHub в одном хранилище: [freemind-club/neurosprint](https://github.com/freemind-club/neurosprint). Ты весь месяц им пользуешься, просто не знал, что это оно. Откроешь — увидишь папки недель и папку со скиллами. Ровно то же самое ты заведёшь себе сегодня.

### Почему это не страшно

Весь страх перед GitHub — это страх «сделаю необратимое». Так вот:

- **Сломать навсегда нельзя.** История помнит всё. Испортил файл — вернул вчерашний. Удалил не то — вернул.
- **Твоё приватное хранилище не видит никто.** Посторонний по ссылке получит 404 — для него такой страницы просто нет.
- **Случайное не страшно.** Любое «ой, я случайно» лечится возвратом одной версии одного файла, не трогая остальное.
- **Ничего не публикуется само.** Чтобы что-то стало видно людям, нужно отдельное действие и отдельное «да». Само — никогда.

### «До звёзд»: что бывает дальше

Это не задача на сегодня, просто чтобы ты видел горизонт.

Сделал свой скилл → открыл его людям → незнакомые люди ставят ему звёзды и делают форки, то есть забирают и переделывают под себя. Через полгода ссылка на твоё хранилище работает как портфолио, которое не надо обновлять: оно само показывает, что ты умеешь и как часто работаешь. Людей, которые находят специалиста через GitHub, больше, чем кажется.

### Одна честная оговорка

GitHub — иностранный сервис, и интерфейс местами на английском. Кнопок, которые нужны в этом уроке, всего несколько, и каждая названа в тексте своим английским словом там, где она понадобится, — но готовься к английским словам на сайте.

> **Про VPN честно: не проверяли.** С сервера Нейроспринта GitHub на разведке открывался нормально — и каталог скиллов, и загрузка файлов работали без всяких обходов. А вот откроется ли `github.com` **в твоём браузере, с твоего интернета и твоего провайдера**, мы не проверяли и утверждать не будем. Не открылся — включи тот же VPN, которым пользуешься для Instagram, и всё. На серверную часть урока это никак не влияет.

## Шаг 0. Доступ: аккаунт за 5 минут и вход по коду

Это единственный блок урока, где ты работаешь руками, а не словами. Причина простая и её надо знать заранее.

> **Проверено до урока, целиком.** Путь «словами» работает до конца — но только после одного ручного входа. Пока входа нет, Гермес честно говорит сам: *«GitHub не настроен — на этом сервере ещё не логинились»*. Как только вход сделан, он создаёт приватное хранилище и отправляет файлы сам, без терминала: на прогоне 19.10 — **72 секунды** до вопроса «сохраняем?» и **2 минуты 49 секунд** после «да». Локальная часть (хранилище на сервере, список запретов, первое сохранение) — **5,5 минуты**, откат файла — **около двух минут**. Поэтому сначала 10 минут доступа, потом всё остальное словами.

> **Как было на эфире: этого блока в записи нет.** Вход `gh auth login` и три настройки git я живьём не показывал — на моём сервере они давно сделаны, повторять было нечего: «я вводить не буду, у меня уже есть». Так что шаги 0б и 0в иди по тексту, он выписан по порядку. Застрял — в чат потока, разберём отдельно.

### 0а. Регистрация (3–5 минут, бегло)

Если аккаунт есть — пропускай, иди к 0б.

1. Открой [github.com](https://github.com) → кнопка **Sign up**.
2. Почта → пароль → **имя пользователя** (это то, что будет в твоих ссылках).
3. На почту придёт **код** из 8 цифр — впиши его.
4. Дальше GitHub задаёт пару вопросов «для кого вы используете GitHub» — можно жать **Skip personalization**.
5. Готово. Твой адрес теперь `github.com/ИМЯ-ПОЛЬЗОВАТЕЛЯ`.

Этого экрана на эфире не было — аккаунт у меня давно заведён. Проходи эти пять пунктов сам, по тексту: это 5 минут, и остальные шаги от регистрации не зависят.

**Про двухфакторку (вход по коду из приложения).** Включить стоит — это 2 минуты и аккаунт не угонят. Но **новому аккаунту она не обязательна и урок тебе не заблокирует.** GitHub требует её только у тех, кто попал в его выборку по активности — такому человеку приходит отдельное письмо. Нет письма — ничего делать не надо.

> **С эфира, чего нет выше: поставь приложение GitHub на телефон.** Оно бесплатное и закрывает сразу две мелочи — подтвердить вход по коду и держать двухфакторку под рукой, не бегая за вторым окном браузера. Не обязательно, но с ним спокойнее.

### 0б. Вход с сервера — по коду, как в Nous на уроке 0

Открой терминал с сервером (Netcatty) и напиши одну команду:

```bash
gh auth login
```

Дальше четыре вопроса, отвечаешь стрелками и Enter:

| Вопрос | Ответ |
|---|---|
| `Where do you use GitHub?` | **GitHub.com** |
| `What is your preferred protocol?` | **HTTPS** |
| `Authenticate Git with your GitHub credentials?` | **Yes** ← важно, это автонастройка |
| `How would you like to authenticate?` | **Login with a web browser** |

Появится **код вида `ABCD-1234`.** Скопируй его, открой на телефоне или во втором окне [github.com/login/device](https://github.com/login/device), впиши код, нажми **Authorize**. Вернись в терминал — там уже написано, что всё хорошо.

Проверка:

```bash
gh auth status
```

**Это ровно тот жест, который ты уже делал на уроке 0 с Nous Portal:** открыл сайт, вписал код, вернулся. Ничего нового.

> **Если кто-то просит у тебя пароль от GitHub — это не твой сотрудник.** Пароли для работы с хранилищами GitHub не принимает с 2021 года. Ни Гермес, ни Архивариус, ни один скилл не должны просить пароль, код из СМС или код двухфакторки. Пароль вводится только на самом сайте github.com, в браузере, своими руками.

### 0в. Три настройки, которые экономят час паники

Теперь уже **словами**. Вкладка **Chat** у Гермеса:

```
Сделай три настройки git на этом сервере и покажи результат каждой одной строкой.
1. Подпиши меня, чтобы точки сохранения были от моего имени: имя «Имя Фамилия», почта «та, что у меня в аккаунте GitHub».
2. Включи показ русских имён файлов как есть, а не кодами: core.quotepath false.
3. Пусть новая ветка называется main: init.defaultBranch main.
```

Зачем каждая:

- **Имя и почта.** Без них первый же твой коммит упадёт с ошибкой *«Please tell me who you are»*. У большинства на свежем сервере их нет. Почту берём ту же, что в аккаунте GitHub, — иначе сохранения не привяжутся к твоему профилю.
- **Русские имена файлов.** Без этой настройки твой файл `пост-про-выгорание.md` показывается так: `"\320\277\320\276\321\201\321\202-..."`. Выглядит как «я всё сломал», а это просто кодировка.
- **`main` вместо `master`.** Мелкая несостыковка между версиями, которая иногда ломает отправку. Чиним заранее.

> **Проверено до урока.** Абракадабра с русскими именами и лечение одной командой проверены живьём на сервере: до настройки — коды, после — `пост-про-выгорание.md`. А ещё: `git` и `gh` на сервере Нейроспринта **уже стоят** (версии 2.34.1 и 2.92.0), ставить ничего не надо. Если у тебя их почему-то нет — команды установки в блоке [для технарей](#для-технарей-и-тех-кто-любит-читать).

## Шаг 1. Нанимаем Архивариуса

Как на уроках 1 и 3: у Гермеса появляется отдельный сотрудник со своей ролью. Его зовут **Архивариус**, внутри это профиль `arhivarius`. Он отвечает за одно — чтобы твоя работа не пропала и не утекла. Содержание документов не его дело: оффер пишет Продуктолог, ролики разбирают Рилсы.

Нанимаем в два коротких шага: **профиль создаём словами, скиллы раскладываем командами.** Так честнее. Полный найм словами мы прогнали живьём — он занял 4 минуты 36 секунд и всё равно разложил скиллы так, что сотрудник их не увидел. Командами это одна секунда и всегда правильно.

### 1а. Профиль сотрудника — словами

**Сообщение в Chat:**

```
Создай мне нового сотрудника: профиль arhivarius копией себя, описание «Архивариус: хранит мою работу в приватном хранилище на GitHub, делает точки сохранения, возвращает вчерашние версии файлов, читает чужие скиллы до установки, помогает опубликовать своё». Дальше по шагам, после каждого коротко доложи.
1. Включи ему автозагрузку двух скиллов: komanda-arhivarius и neurosprint-4-github.
2. Поставь ему самую дешёвую из рабочих моделей — он складывает файлы, а не пишет тексты.
3. Покажи список его подключений (MCP) и удали их все: он работает с моими файлами, лишний доступ ему не нужен.
4. Итог по одной строке: профиль arhivarius создан / модель такая-то / автозагрузка включена / MCP пусто.
```

Посмотри глазами: на вкладке **Profiles** появилась карточка `arhivarius`.

## Шаг 2. СОХРАНИТЬ своё

Три дела подряд: завести закрытый сейф → решить, что в него **не** попадает → сохраниться и убедиться, что ничего не потерялось.

### 2а. Закрытый сейф, а не «папка в интернете»

Хранилище бывает двух видов, и разница простая:

> **Публичное** — как пост в канале: ссылку знает любой, зайти может любой, оно попадает в поиск.
> **Приватное** — как заметка в твоём телефоне: лежит на серверах GitHub, но открыть её можешь только ты под своим логином. Посторонний по ссылке увидит 404 — для него этой страницы просто не существует.

Твоя работа идёт **в приватное.** Это не навсегда: отдельные вещи мы потом аккуратно откроем на шаге 5.

### 2б. Что НЕ кладём — решаем ДО первого сохранения

Это самый важный разговор урока. Причина — в том, как устроена история: **один раз попало — считай, утекло навсегда.** Можно удалить файл сегодня, но он останется в истории версий. Поэтому решаем заранее, а не «потом почистим».

| Не уходит в хранилище | Почему |
|---|---|
| `.env`, любые ключи, токены, пароли в текстовых файлах | история помнит всё; «приватное» не значит «зашифрованное» |
| Выгрузки клиентов: списки, телефоны, переписки, CRM-экспорт, базы | это чужие персональные данные, не твои, чтобы хранить их на чужом сервере |
| Скриншоты с личным: чаты, суммы, фамилии | то же самое, только незаметнее |
| Паспорта, сканы, реквизиты | персональные данные |
| Видео, большие архивы, установщики | файл больше 50 МБ GitHub примет с предупреждением, больше 100 МБ не примет вообще |
| Чужие файлы: клиентские документы, купленные материалы | не твоё |

**Правило одной строкой: GitHub — для текста. Видео, выгрузки и ключи — не в GitHub.**

### 2в. Папка «личное» — главный приём этого урока

Обычный способ защититься — запретить файлы по названию: «не брать всё, где есть слово „клиенты“». Так делает и сам Гермес, если его не остановить. **Это ловушка, и вот почему.**

> **Проверено до урока — и это главная грабля недели.** Гермес сочинил список запретов, в котором были маски `*клиенты*` и `*.csv`. Проверка показала: обычный рабочий документ `мои-клиенты.md` **молча не попал в сохранение.** Не ошибка, не предупреждение — просто тишина. Человек уверен, что всё сохранено, а файла в сейфе нет. Самый опасный список запретов — не тот, что пропускает лишнее, а тот, что **молча глотает нужное.**
>
> На последнем прогоне, уже со скиллом недели, масок он не сочинил вовсе — наоборот, сам написал в списке комментарий «масок по словам в названии нет, они молча съедают рабочие файлы». Но если у тебя сочинит, лечится одной фразой ниже.

Поэтому мы не угадываем по названиям. Мы завели **папку-карантин**: всё личное, клиентское и секретное кладём в папку `личное/`, и она целиком никуда не уходит. Понятно, не ломается от переименований, видно глазами.

### 2г. Сохраняемся

> 🔴 **Сначала — главное про Архивариуса: слово «сохрани» он понимает широко.** На прогоне перед уроком, на эту самую фразу, он не остановился на сервере: **сам создал хранилище на GitHub, сам придумал ему название и сам отправил туда файлы.** Названия я не говорил, разрешения он не спрашивал. Это не вредность — для него «сохрани работу» значит «доведи до конца, чтобы не пропало», а конец — это GitHub.
>
> Лечится не уговорами, а одной строкой в твоей же фразе:
>
> **«Ничего на GitHub пока не создавай и не отправляй — сначала покажи мне список и дождись моего „да“».**
>
> Слова «дождись моего „да“» — это его стоп-кран. С ними он показывает список и ждёт (проверено). Без них может уехать сразу. Поэтому **этот ограничитель стоит в конце каждой фразы урока, где мы просим сохранить или навести порядок до момента, когда отправляем осознанно** — ты увидишь его много раз, это не опечатка и не перестраховка.
>
> В скиллах недели это уже поправлено (версия 1.0.2): теперь он обязан спрашивать всегда, а не только когда его попросили подождать, и не имеет права придумывать название хранилища сам. Но привычку дописывать ограничитель словами оставь: она работает с любым агентом и любой версией скилла.

**Сообщение в Chat** (эта формулировка проверена живьём, работает):

```

Потом покажи простым языком, что именно попало в сохранение, а что осталось снаружи. Ничего на GitHub пока не создавай и не отправляй — сначала покажи мне список и дождись моего «да».
```

**Это занимает минут пять.** На прогоне — 5 минут 31 секунда: он правда открывает и читает твои файлы, а не делает вид. Пауза в чате — нормально, не дёргай его повторным сообщением.

**Должно получиться:** список из двух частей — «вошло» и «осталось снаружи, под защитой». Примерно так:

```

  .env — файл с паролями/ключами. Никогда не попадёт в хранилище

```

> **Как было на эфире: ограничитель отработал.** С фразой выше Архивариус сделал точку сохранения **только у меня на сервере** и остановился. Отчёт: локальная точка сохранения, вошло 10 файлов, около тысячи строк — рабочие заметки, код, документы; наружу не ушли ни пароли, ни ключи, папка «личное» и клиенты остались снаружи. И дальше прямой вопрос: «когда делаем push?» — то есть сам он на GitHub не полез. Ровно то поведение, ради которого ограничитель и дописывается.

Теперь, когда доступ к GitHub есть, отправляем:

```
Создай на гитхабе приватное хранилище «razbor-biznesa» и залей туда то, что мы сохранили. Перед отправкой покажи полный список файлов и дождись моего «да». Название хранилища своё не придумывай: если «razbor-biznesa» занято — скажи мне и предложи варианты. Название точки сохранения сделай человеческое, по сути: «Недели 0–3: точка А, клиент, оффер, разборы роликов».
```

**Вот теперь слова «дождись моего „да“» работают на тебя.** На прогоне он показал два списка — «уходит в хранилище» (6 файлов) и «не уходит» (`.env` — ключи, `личное/выгрузка клиентов.csv` — данные клиентов), добавил от себя строку «если нужного файла нет в списке „уходит“ — он попал под запрет, скажи мне» и остановился с вопросом «сохраняем?». 72 секунды до вопроса, 2 минуты 49 секунд после «да» — и хранилище на GitHub готово.

**Проверь глазами.** Открой `github.com/ТВОЁ-ИМЯ?tab=repositories` — хранилище на месте, рядом с названием написано **Private**. Зайди внутрь: файлы видно, `.env` и выгрузки — нет.

### 2д. Ритуал проверки: ничего ли не потерялось

Не верь на слово — ни Гермесу, ни себе. **Каждый раз после настройки списка запретов спрашивай одно и то же:**

```
Покажи списком: какие файлы из этой папки уедут на GitHub, а какие нет. И если что-то нужное не уезжает — скажи, из-за какого именно правила и какой строки списка запретов. Ничего пока не отправляй — я сначала прочитаю список глазами.
```

Глазами сверь: все твои рабочие документы в первом списке? Во втором списке только то, чему там и место? Если какой-то нужный файл оказался «не уезжает» — ты только что поймал ту самую молчаливую грабля, и это нормально. Правило убирается, файл переносится из-под запрета.

> 🔴 **Что он ловит, а что нет — по факту, а не по надежде.** Проверено живьём, двумя прогонами:
>
> - **`.env` он не пропускает** — но не потому, что внимательный, а потому, что этот файл стоит в списке запретов по точному имени. Защита здесь механическая, и именно поэтому она работает.
> - **`выгрузка клиентов.csv` с телефонами он сам по названию НЕ ловит.** В разведке — не заметил. На последнем прогоне файл не уехал только потому, что уже лежал в папке `личное/`. То есть спас его карантин, а не внимательность агента.
>
> Так что считай так: **Гермес — помощник, но не фильтр.** Рабочая защита — это список запретов по точным именам и папка `личное/`. Решаешь, что в карантине, ты, своими руками и глазами, до первого сохранения.

### 2е. Проверь своими глазами, что точка сохранения есть

Минута после каждого сохранения — и дальше спокойно.

**Словами:**

```
Покажи историю точек сохранения: последние три строки — дата, название, короткий номер. И скажи, есть ли в ней та точка, которую ты только что сделал.
```

**На сайте, глазами:** открой своё хранилище → над списком файлов строка **«N commits»** (или кнопка **Commits**) → список точек сохранения с датами и названиями. Клик по точке — видно, какие файлы в неё вошли. Это та же история, только картинкой.

> 🔴 **Зачем это обязательно.** На прогоне перед уроком Архивариус на просьбу «сделай точку сохранения» ответил через 42 секунды: «готово, файл изменён, +4 строки». А точки **не было** — история её не показывала. Он не врал нарочно, он отчитался о том, что собирался сделать. Лечится одной фразой: *«Точки сохранения в истории нет, история её не показывает. Сделай точку сохранения по-настоящему и покажи историю»* — после этого она появилась за 49 секунд.
>
> Отсюда правило на всю жизнь с любыми агентами: **верим истории, а не отчёту.** «Готово» — это не доказательство. Доказательство — строка в истории, которую ты видишь своими глазами.

## Приватный ≠ безопасный: читай это дважды

Самое честное место урока.

**Приватное хранилище — это про «кто видит». Список запретов — про «что вообще туда попадает». Нужны оба.**

И отдельно, прямым текстом, без обещаний, которых никто не сдержит:

> **У GitHub есть защита, которая ловит случайно отправленные ключи и не даёт их отправить. Она работает бесплатно ТОЛЬКО в публичных хранилищах.** У тебя хранилище приватное — значит **этой сетки под тобой нет.** Если ключ уедет, GitHub тебя не остановит и даже не предупредит.

Поэтому реальная защита у тебя ровно одна, и она локальная: **список запретов плюс папка `личное/`** — она работает механически, всегда, независимо от настроения модели. Гермес к этому помощник, а не второй контур: выгрузку клиентов по названию он сам не поймал ни на разведке, ни на прогоне (см. врезку в [2д](#2д-ритуал-проверки-ничего-ли-не-потерялось)). Решаешь, что уходит наружу, ты.

> **Как было на эфире — и поправка к моим же словам.** На записи я пару раз сказал, что публичный GitHub «проверяет и убирает ключи автоматически». Формулировка неточная, держи правильную: защита GitHub ключ **не убирает и не чистит** — она **не даёт отправке пройти** и показывает, что именно нашла, а решение всё равно за тобой. И да, работает она бесплатно только на публичных хранилищах: в приватном сейфе, где лежит твоя работа, её нет вовсе. Суть от этого не меняется — за содержимое закрытого сейфа отвечаешь ты один.

Забавный побочный вывод, который стоит запомнить: **делиться безопаснее, чем хранить.** На шаге «отдать» защита появляется, а в закрытом сейфе её нет.

**Если ключ всё-таки уехал — порядок действий, и порядок здесь важнее всего:**

1. **Сначала поменяй сам ключ** в том сервисе, где он выдан. Это единственное действие, которое реально закрывает дыру. Ключ, который побывал в интернете, считается украденным — даже если «никто не видел».
2. **Потом** убирай его из хранилища и из истории.
3. Чистка истории **не гарантирует**, что никто не успел скопировать.

> **Одной фразой: утёк ключ — первым делом меняешь ключ, а не чистишь GitHub. GitHub почистишь вторым делом. Наоборот — бессмысленно.**

## Шаг 3. ОТКАТ: «сломал файл — вернул вчерашний»

То, ради чего всё это и нужно. Два пути, и они делают разное.

**Но сначала — ещё одна точка сохранения.** Вернуться можно только к тому, что сохранено, а мы после первого сохранения уже что-то правили. Поэтому перед экспериментом:

```
Я поправил файлы после прошлого сохранения. Сделай ещё одну точку сохранения и покажи историю — последние три строки. Ничего на GitHub пока не создавай и не отправляй — сначала покажи мне список и дождись моего «да».
```

И сразу сверь глазами, что точка в истории действительно появилась — [как это делать, в 2е](#2е-проверь-своими-глазами-что-точка-сохранения-есть). Это ровно тот шаг, на котором на прогоне агент сказал «готово», а сохранения не было.

### 3а. Сайт — чтобы УВИДЕТЬ историю

Открой своё хранилище на GitHub → клик по файлу → сверху справа кнопка **History**. Увидишь список версий: кто менял, когда, с каким комментарием. Клик по версии — файл в том виде, какой был тогда.

Это стоит сделать руками хотя бы раз. Когда ты своими глазами видишь, что все твои версии живы и лежат по датам, страх «сломаю и потеряю» проходит окончательно.

> **Как было на эфире.** Историю я показывал не на демо-сейфе, а на публичном хранилище курса: открыл папку недели 2 и папку недели 3 и нажал **History**. У недели 2 с момента записи урока не менялось ничего, у недели 3 видно несколько правок за две недели — даты, названия, что именно поменялось. Жест тот же самый, просто на живом примере, который открыт у всех. Своё хранилище смотришь точно так же.

> **Важно и неочевидно: кнопки «восстановить файл» на сайте GitHub НЕТ.** Сайт умеет только показать старую версию, дать её скопировать (кнопка **Raw**) и скачать. Вернуть через сайт можно только вручную: скопировал старый текст → карандаш (**Edit**) на файле → вставил → **Commit changes**. Это копипаста, и она работает, но это не то, чем стоит заниматься.

### 3б. Гермес — чтобы ВЕРНУТЬ

Одной фразой. Проверено живьём, самый надёжный блок урока: 1 минута 29 секунд до вопроса «это та версия?» и ещё 29 секунд после «да» — около двух минут всего.

```
Я случайно испортил файл 03-offer.md, там теперь ерунда. Верни, пожалуйста, предыдущую версию, которая была до того, как я его переписал. Сломанную версию сохрани рядом как 03-offer-slomannyi.md, чтобы ничего не потерялось. Перед тем как вернуть, покажи 2-3 строки из старой версии — я подтвержу, что это та. На GitHub пока ничего не отправляй — сначала покажу себе результат глазами.
```

**Должно получиться:** Архивариус находит последнюю целую версию, называет её дату, показывает обе версии рядом («вот что там сейчас» / «вот что верну»), ждёт твоего «да», возвращает **один файл** и не трогает остальные. На прогоне он ещё и сам предложил сделать точку сохранения после возврата — это правильно, согласись.

**Мелочь, на которой легко растеряться:** сломанную версию он кладёт **рядом с файлом**, то есть в ту же подпапку (например в `документы/`), а не в корень рабочей папки. Ищи её там.

Запомни формулу: **сайт показывает — Гермес делает.**

### 3в. Бонус, который понравится всем: «что изменилось с прошлой недели»

```
Расскажи по-человечески, что изменилось в моём хранилище с прошлой недели: какие документы менялись, какие появились, в чём суть изменения — одной строкой на документ. Без технических сравнений построчно.
```

Получишь что-то вроде:

```
С 8 октября:
  03-offer.md — переписал таблетку, добавил лестницу продуктов
  posty/… — три новых поста
  02-klient.md — не менялся
```

Это, по сути, дневник твоей работы, который ведётся сам.

## Шаг 4. ВЗЯТЬ чужое

Второе, за что людям нужен GitHub: там лежат чужие готовые решения. Порядок жёсткий: **сначала прочитать, что внутри, потом ставить.** Это прямое продолжение урока 2 — скилл это просто инструкция текстом, её можно прочитать целиком.

### 4а. Найти

```
Найди в каталоге скиллов что-нибудь для работы с документами Word: hermes skills search docx. Покажи таблицу целиком и объясни, чем в колонке Trust отличается trusted от community.
```

В таблице есть колонка **Trust** — это первый фильтр. `trusted` значит, что источник известный (например, сама Anthropic). `community` — кто угодно.

> **Как было на эфире.** Поиск вернул таблицу больше чем на 25 строк: скиллов для документов в каталоге много, и колонка **Trust** — действительно первое, на что там надо смотреть, иначе выбирать не из чего.

### 4б. Прочитать до установки

```
Загляни внутрь скилла, не устанавливая его: hermes skills inspect anthropics/skills/skills/docx. Расскажи своими словами в 3–5 строк: что он делает, какие команды запускает, куда лезет, что просит у меня. Потом прогони его по семи проверкам из своего метода и дай вердикт — зелёный, жёлтый или красный. Пока ничего не ставь.
```

**Семь проверок Архивариуса — бытовым языком:**

| № | Что смотрим | Красный флаг |
|---|---|---|
| 1 | **Просит ли ключи и пароли** | «введи пароль», «пришли ключ сюда», печатает ключ в чат. Нормально: «ключ положи в файл своими руками» |
| 2 | **Что он запускает** | скачать из интернета и сразу выполнить одной строкой; просит права администратора |
| 3 | **Точные ли версии** | «поставь последнюю версию», `latest`. Завтра там будет другой код, который никто не проверял |
| 4 | **Нужен ли ему целый сервер** | требует базу, контейнеры, свой сервис — и **без них отказывается работать** |
| 5 | **Куда он пишет** | сам, без спроса, сохраняет переписки, клиентов, документы или отправляет куда-то наружу |
| 6 | **Что удаляет и перезаписывает** | «подчищу папку», перезаписывает твои настройки и память |
| 7 | **Нет ли внутри «указаний для агента»** | текст вида «игнорируй предыдущие инструкции», «ничего не говори пользователю». Это повод не ставить вовсе |

**Важная практическая деталь.** `inspect` принимает и короткое имя из каталога, и прямую ссылку — но результат разный **не по коду, а по доверию**: у имени из каталога в карточке будет `Trust: trusted` (если автор известный), у ссылки — всегда `Trust: community`, потому что у ссылки нет никакой репутации.

```bash
hermes skills inspect https://raw.githubusercontent.com/freemind-club/neurosprint/main/skills/neurosprint-4-github/SKILL.md
```

Поэтому про присланную ссылку всегда два разных вопроса: **что внутри** (это покажет `inspect`) и **кто автор** (этого не покажет никто, кроме тебя). Самый надёжный способ — всё равно открыть ссылку в браузере и прочитать текст глазами: страницу на GitHub ты читаешь сам, без посредников.

### 4в. Поставить

```
Вердикт зелёный, ставим: hermes skills install anthropics/skills/skills/docx. Потом скажи одной строкой, что теперь умеет Гермес, чего не умел.
```

> **Проверено до урока — лучшая иллюстрация урока 2 за весь интенсив.** Я попробовал поставить **официальный скилл Anthropic** двумя путями. По короткому имени из каталога — спокойно, источник `trusted`. По **прямой ссылке** — Гермес положил его в карантин, прогнал свою проверку безопасности, нашёл 6 подозрительных мест и **заблокировал установку сам**:
>
> ```
> Quarantined to .hub/quarantine/docx
> Scan: docx   Verdict: CAUTION
>   HIGH     exfiltration   scripts/office/soffice.py:28   "env = os.environ.copy()"
>   MEDIUM   supply_chain   SKILL.md:21   "`docx` is preinstalled…"
> Decision: BLOCKED — Blocked (community source + caution verdict, 6 findings).
> ```
>
> **Это один и тот же код.** Разный вердикт — потому что меняется доверие **к источнику**, а не к коду: у ссылки нет никакой репутации. Ровно та мысль, с которой мы жили весь урок 2.
>
> Два вывода, оба практические: **ставь по имени из каталога, а не по ссылке из чата** — по имени Гермес знает, кто автор. И: у блокировки есть кнопка обхода `--force`. Это кнопка «я понимаю, что делаю». **Не понял, что нашёл сканер — не жми.**
>
> **На эфире это повторилось один в один.** Я специально прошёл оба пути ещё раз: по короткому имени из каталога скилл встал спокойно, а по прямой ссылке Гермес сразу отправил его в карантин и назвал подозрительным — сам, без моей просьбы. Значит, это не случайность прогона, а штатное поведение.

## Шаг 5. ОТДАТЬ своё

Третье, за что GitHub нужен: отдать свою работу людям одной ссылкой. Клубу, клиентам, студентам.

### 5а. README — это витрина, а не документация

Публичное хранилище без README — дверь без вывески. Его читают **20 секунд** и решают, брать или нет. Шесть блоков:

1. **Что это и для кого** — одна строка по-человечески. Не «skill for agent», а «Скилл для Гермеса: разбирает Telegram-канал по выгрузке и говорит, что работает».
2. **Как поставить** — одна команда, копипастой.
3. **Что нужно, чтобы заработало** — какие ключи, доступы, файлы. Честно: «нужен свой ключ OpenAI» — это уважение к читателю.
4. **Пример: что на входе → что на выходе** — лучше всего 5 строк «до / после».
5. **Чего НЕ делает** — экономит людям час и снимает всё разочарование.
6. **Автор и как написать** — ник в Telegram. Это и есть смысл «отдать»: по README тебя находят.

**Сообщение в Chat:**

```
Собери README для моего скилла по шаблону витрины: что это одной строкой, для кого, что делает (3–5 пунктов — результатами, а не процессом), как поставить одной командой, что нужно чтобы заработало, пример «на входе → на выходе» в 5 строк, чего скилл НЕ делает, автор и как со мной связаться. Версию поставь 1.0.0. Сохрани файлом README.md рядом со скиллом и покажи мне текст целиком. Ничего на GitHub пока не создавай и не отправляй — сначала покажи мне список и дождись моего «да».
```

### 5б. Проверка «нет ли внутри личного»

Отдельный шаг, пропускать нельзя. Публичное читают все, включая поисковики.

```

### 5в. Два отдельных «да» на публикацию

**Проверено: правило держит.** На прямой вопрос «что ты спросишь, прежде чем открыть хранилище людям» Архивариус выдал свой порядок из **двух отдельных «да»**: сначала закрыть проверку на личное и согласовать замены, потом показать финальный список файлов и дождаться «да» **на список**, и только после этого задать вопрос про публикацию и дождаться «да» **на публикацию**.

Это не бюрократия. Публикация — **единственная необратимая кнопка во всём уроке**, поэтому она и стоит двух подтверждений.

Архивариус обязан спросить тебя прямым текстом — и это не формальность:

> «Это станет видно любому человеку в интернете и попадёт в поиск. Убрать потом можно, но копии могут остаться. Публикуем?»

Твой ответ:

```
Список пуст, личного внутри нет. Да, публикуем: сделай хранилище «moi-skill» публичным и дай мне ссылку, которой можно поделиться, плюс одну строку текста для клуба.
```

**Ссылка получится вида** `github.com/ТВОЁ-ИМЯ/moi-skill`.

> **Честно: этот последний шаг мы живьём не прогоняли.** В прогоне перед уроком мы дошли до вопроса «публикуем?» и сознательно остановились — демо-хранилище с рабочими файлами публиковать было незачем. Команды и путь по сайту выписаны и проверены по документации, но сам момент смены видимости на публичную ты, возможно, увидишь раньше меня. Если что-то пойдёт не так — напиши в чат потока, разберём.

Через сайт глазами то же самое: хранилище → **Settings** → в самый низ страницы → **Danger Zone** → **Change visibility** → **Make public** → подтвердить вводом имени хранилища. GitHub специально просит подтверждение дважды — он тоже считает это необратимым.

**Разослать ссылку — твоя работа, не Архивариуса.** Он готовит и показывает, публикуешь и делишься ты сам. Как и везде в Нейроспринте.

<summary><b>Открыть техническую часть (необязательно, урок проходится и без неё)</b></summary>

Все команды ниже проверены на сервере Нейроспринта: Ubuntu 22.04.5, `git` 2.34.1, `gh` 2.92.0.

### Если `gh` не установлен

Официальный путь GitHub для Ubuntu/Debian — их собственный apt-репозиторий:

```bash
sudo mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null
sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
  | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt update && sudo apt install gh -y
gh --version
```

Если apt-репозиторий недоступен — бинарник из GitHub Releases: `https://github.com/cli/cli/releases/latest`, распаковать, положить `bin/gh` в `/usr/local/bin/`.

### Вход и настройки

```bash
gh auth login            # GitHub.com → HTTPS → Yes → Login with a web browser
gh auth status           # кто я сейчас
gh auth setup-git        # gh становится credential-helper'ом для git, пароли больше не спрашиваются
gh auth switch           # переключить аккаунт, если их несколько
gh auth logout

git config --global user.name "Имя Фамилия"
git config --global user.email "почта-из-аккаунта-github"
git config --global core.quotepath false      # русские имена файлов как есть
git config --global init.defaultBranch main   # git 2.34 по умолчанию делает master, GitHub ждёт main
```

Токен после входа лежит в `~/.config/gh/hosts.yml` с правами `600` — на headless-сервере без keyring `gh` пишет его в обычный файл. Точное место всегда покажет `gh auth status`. Потерял сервер — GitHub → Settings → Applications → отозвать доступ.

Запасной путь, если вход по коду не идёт (нет доступа к сайту в тот же момент, корпоративная сеть): fine-grained токен — GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → срок 90 дней → Repository access: Only select repositories → Permissions: **Contents: Read and write** + **Administration: Read and write** (нужно для создания хранилищ). Отдавать токен так, чтобы он не попал в историю команд:

```bash
gh auth login --with-token < путь-к-файлу-с-токеном
```

`gh` в хелпе предупреждает: fine-grained токены лучше отдавать через переменную `GH_TOKEN` — `--with-token` рассчитан на classic, и узкие права дают странное поведение на части операций.

### Лимиты GitHub

| Порог | Что происходит |
|---|---|
| 25 МиБ | предел загрузки файла через браузер |
| 50 МиБ | предупреждение, отправка проходит |
| 100 МиБ | **отправка блокируется** |
| ~1 ГБ на хранилище | рекомендуемый максимум, не жёсткий |

Защита от утечки секретов (push protection) бесплатна **только для публичных** хранилищ. Для приватных нужна платная GitHub Secret Protection — на бесплатном личном тарифе её нет.
