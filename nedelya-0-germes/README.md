# Урок 0. Гермес с нуля: от пустого сервера до помощника в Telegram

*Нейроспринт · урок 0 · проходится в любой момент, до недели 1*

**Что будет в конце урока.** На твоём сервере живёт помощник — Гермес. Ты пишешь ему в Telegram с телефона, как обычному человеку, и он отвечает. У него есть веб-интерфейс в браузере и доска задач. И всё это работает **бесплатно**: никаких ключей, никаких подписок, никакой карты. Опыт программирования не нужен — ты вводишь две готовые команды, остальное делаешь мышкой и словами.

**Сколько времени.** Весь урок — **40–60 минут**. Если повезёт с интернетом — быстрее. Если будешь ждать домен — до полутора часов. На записи урока я прошёл всё на чистом сервере за 40 минут вместе со всеми ошибками — и показал, как каждую из них лечить.

> **Это тот урок, после которого можно идти в любую неделю интенсива.** Если ты пришёл в поток позже и у тебя ещё ничего не стоит — ты по адресу.

### Главное правило урока

**Гермеса ставят ровно две команды.** Первая ставит Гермеса, вторая подключает Telegram. Всё остальное — вопросы на экране, кнопки в браузере и обычные слова. (Ещё пара коротких команд — обновить систему, открыть веб-интерфейс без домена и закрыть лишние порты — тоже готовые, их только скопировать.)

Команды **копируй кнопкой копирования** в правом верхнем углу блока. Не перепечатывай руками и не пересылай через Word — там команда ломается, а почему, написано в [«если что-то не так»](#если-что-то-не-так).

> **Пароли, токены и коды никогда не отправляй в чат** — ни в чат потока, ни боту, ни на скриншотах. Если делаешь скрин для вопроса — закрой строки с длинными наборами букв и цифр.

## Что нужно до начала

Сервер у тебя уже есть — покупку мы в этом уроке не разбираем. Проверь только, что он подходит:

| Что | Сколько нужно | Почему именно столько |
|---|---|---|
| Операционная система | **Ubuntu 24.04** | под неё написан установщик |
| Процессор | **4 ядра** хватит, 6 — лучше | помощник и его будущие сотрудники работают одновременно |
| Память | **4 ГБ — минимум**, в идеале 8 ГБ | 2 ГБ — совсем впритык: заведётся только с файлом подкачки (шаг 3), и места для роста не будет. Со временем добавятся агенты и другие программы, и всё это ест память |
| Свободное место на диске | **минимум 10 ГБ**, рекомендую 60 ГБ и больше | сама установка весит около 5–6 ГБ: помощник приносит с собой свой Python, свой браузер и ещё кучу всего. Запас нужен, если потом захочешь поставить на сервер свои нейросети |
| Доступ | IP-адрес сервера и пароль `root` | пришли на почту от хостинга |
| Telegram | на телефоне | через него ты будешь работать каждый день |
| Компьютер | Windows или Mac | программа Netcatty для установки и браузер |
| Домен *(необязательно)* | любой свой | нужен только для веб-интерфейса, [шаг 8](#шаг-8-веб-интерфейс-твой-офис-из-любой-точки-мира). Есть путь и без домена |

> **Почему на сервере, а не на своём компьютере.** Поставить Гермеса себе на компьютер можно, но тогда он работает, только пока компьютер включён. Сервер не выключается никогда: помощник на связи 24/7, даже когда ноутбук закрыт.

> **Python, Node.js и прочие страшные слова ставить НЕ нужно.** Гермес приносит себе всё своё: свой Python, свой Node, свой браузер, свой ffmpeg. Твоя задача — два раза вставить команду.

> **Если дальше планируешь [неделю 1](../nedelya-1-jev-laya/README.md)** — там в третьей части ставится модель прямо на сервер, и ей нужно **8 ГБ памяти**. Для урока 0 это не обязательно: всё, что мы делаем сегодня, живёт и на 2 ГБ.

**Домен — сделай заранее, если он есть.** В панели, где управляешь доменом, добавь запись **A**: имя `agent`, значение — IP твоего сервера. Получится адрес `agent.твой-домен.ru`. Запись «расходится» по интернету 5–30 минут, поэтому лучше сделать это за полчаса до урока, а не посреди установки.

Зачем домен вообще: по нему веб-интерфейс помощника открывается из любой точки интернета, по-человечески читаемым адресом. И многие сервисы, которые ты потом захочешь подключить, работают только с доменом, а не с голым набором цифр адреса.

## Шаг 1. Заходим на сервер через Netcatty

Netcatty — бесплатная программа, чтобы «заходить» на сервер. Это как удалённый рабочий стол, только вместо картинок — текст.

1. Открой [страницу загрузки Netcatty](https://github.com/binaricat/Netcatty/releases/latest). Внизу, в списке файлов, выбери свой:
   - Windows — `Netcatty-…-win-x64.exe`
   - Mac на M1/M2/M3/M4 — `Netcatty-…-mac-arm64.dmg`, Mac на Intel — `Netcatty-…-mac-x64.dmg`
2. Установи и открой. Язык переключается на русский в настройках — дальше всё будет по-русски.
   На Mac, если пишет «не удаётся проверить разработчика»: правой кнопкой по Netcatty в «Программах» → **Открыть** → **Открыть**.
3. Добавь новый хост (кнопка **New Host** / «Новый хост») и заполни:
   - **название** — любое, для себя: например, `Мой сервер`;
   - **адрес** — IP сервера из письма хостинга (у нас дальше он везде `IP_сервера`);
   - **порт** — не трогай, оставь как есть;
   - **пользователь** — `root`;
   - **пароль** — из письма хостинга.
4. Внизу нажми **Сохранить**. Сервер появится в списке.
5. Нажми на него — начнётся подключение. Спросит про «fingerprint» / отпечаток ключа — соглашайся, это нормально.

Видишь чёрный экран со строкой вида `root@что-то:~#` — ты внутри. Ничего не боимся, так и выглядит сервер. Всё, что мы будем делать дальше, вставляется сюда.

> **Пишет ошибку подключения?** Чаще всего пароль вбит с опечаткой — у меня на записи было ровно так. Открой хост, перепроверь пароль, сохрани и подключись ещё раз.

## Шаг 2. Обновляем систему и ставим две программы

Новый сервер приходит со старыми программами внутри: образ собрали давно, с тех пор вышли обновления и заплатки безопасности. Поэтому сначала обновляем **всю систему целиком**, а заодно ставим две мелкие программы, без которых установщик Гермеса не поедет. Проверять ничего не надо — одна команда делает всё. Что уже стоит, она не сломает.

```
apt update && apt upgrade -y && apt install -y git curl
```

Займёт 3–5 минут, по экрану побегут строки — это нормально. В конце могут быть строки про службы (`running` и прочее) — это тоже нормально, команда закончилась, когда снова появилась строка `root@…:~#`.

> 🔴 **Если посреди обновления вылезло цветное окно с вопросом** (розовое или синее, например «какие службы перезапустить» или «что делать с файлом настроек») — **просто жми Enter**. Вариант по умолчанию там всегда безопасный: оставить как есть.

- Если в конце увидишь ошибку про «lock» или «не могу получить блокировку» — свежий сервер в первые минуты сам ставит себе обновления. Подожди 5 минут и повтори ту же команду.
- Если в конце написано про перезагрузку (`System restart required` или `Pending kernel upgrade`) — набери `reboot`, подожди минуту и зайди в Netcatty снова. Ничего не потеряется.

## Шаг 3. Команда 1: ставим Гермеса

Скопируй команду целиком, вставь в Netcatty, нажми Enter:

```
bash <(curl -fsSL https://raw.githubusercontent.com/freemind-club/freemind-setup/main/install.sh) hermes
```

Установка займёт **5–10 минут**: скачается несколько гигабайт. Можно смотреть, как бегут строчки, — это нормально, ничего не сломалось.

> **Упало с `curl: (22) The requested URL returned error: 429`?** У меня на записи было именно так. 429 — это сайт Гермеса говорит «слишком много желающих, подожди». Ничего не сломалось. Подожди 1–2 минуты и запусти **ту же команду ещё раз**: то, что уже поставилось, она пропустит.

По ходу установщик задаст несколько вопросов. Часть из них по-русски (это установщик клуба), часть по-английски (это мастер настройки самого Гермеса — он запускается посередине). **Вот они все, в том порядке, как было на записи:**

| Установщик спрашивает | Что делаешь |
|---|---|
| «Добавить своп 4ГБ сейчас? (y/N)» | 🔴 пиши **`y`** и Enter. Просто Enter = **«нет»**, и это ловушка — читай врезку ниже. Если своп на сервере уже есть, установщик напишет «Своп уже есть» и этот вопрос не задаст |
| *Дальше 5–10 минут бегут строки* | ставятся Python, Node и сам Гермес (версия на записи — 0.22.5). Не трогай |
| Меню из трёх строк: `Quick Setup (Nous Portal)…`, `Full setup…`, `Blank Slate…` | выбери первую — **Quick Setup (Nous Portal)**: бесплатный вход, без ключей. Она и так подсвечена → Enter |
| Показывает ссылку и код | это [шаг 4](#шаг-4-подключаем-бесплатный-мозг-nous-portal) — не закрывай окно, переходи туда |
| Список моделей | выбери ту, что помечена **●** (по умолчанию). Подробнее — в шаге 4 |
| `Select terminal backend:` | выбери **`Local`** — «прямо на этой машине». Обычно он уже стоит по умолчанию → Enter |
| `Connect a messaging platform? (Telegram, Discord, etc.)` | выбери **`Skip — set up later`**. Telegram подключим своей командой в [шаге 6](#шаг-6-команда-2-подключаем-telegram) |
| `Install the gateway service so Hermes starts automatically…?` | пиши **`y`** — помощник будет сам запускаться после перезагрузки сервера |
| «Выбери 1 или 2 [1]:» | пиши **`1`** и Enter (или просто Enter — это уже выбрано). Это бесплатный Nous Portal. Вход ты уже сделал, второй раз ссылку обычно не спрашивает |
| Снова список моделей | бери бесплатную по умолчанию, как в первый раз |
| `Send shared metrics to Nous?` | отправлять ли Nous статистику использования. Я ответил **`n`** — нам это не нужно. Решай сам, на работу не влияет |
| «Doctor нашёл замечания выше» | это самопроверка, жёлтые замечания — не поломка. Установка идёт дальше |
| «Демо-задача для Kanban» | просто Enter. Это учебная задачка для доски, она нужна |
| «Ждём выполнения демо-задачи…» | так и задумано: примерно минуту помощник выполняет демо-задачу. Не трогай |
| «Привязать дашборд к домену (https)? (y/N)» | есть домен — **`y`**, нет домена — **`n`**. Что выбрать, разобрано в [шаге 8](#шаг-8-веб-интерфейс-твой-офис-из-любой-точки-мира) |
| «Домен» *(только если ответил y)* | `agent.твой-домен.ru` — тот, что готовил заранее |
| «Email для Let's Encrypt» *(только если y)* | твоя почта. На неё придут письма, если сертификат когда-нибудь будет истекать |
| «Пароль для входа в дашборд (логин admin)» *(только если y)* | 🔴 придумай свой, **только латинские буквы и цифры**, 12 знаков и больше. Читай вторую врезку |

> 🔴 **Первый вопрос — про своп, и на нём ошибаются почти все.**
>
> Своп (он же «файл подкачки») — это **запасная память на диске**. Когда настоящая память кончается, система откладывает часть данных туда и продолжает работать. Без свопа она просто убивает программу, которая не поместилась.
>
> Гермес в момент установки жадный. На сервере с 1–2 ГБ памяти **без свопа он почти гарантированно ляжет** — причём молча: установка просто оборвётся или поставится криво, и бот потом будет отвечать через минуту или умирать.
>
> Поэтому: **увидел вопрос про своп — пиши `y`.** На Enter установщик по умолчанию отвечает «нет» — это ему так положено, но нам не подходит.
>
> Уже установился без свопа? Не страшно. Напиши потом Гермесу в чат: *«добавь своп 4 ГБ и прописи его в fstab, чтобы он остался после перезагрузки»* — он сделает сам.

> 🔴 **Пароль: только латиница и цифры. Апостроф ломает установку.**
>
> Пароль, который ты вводишь для веб-интерфейса, установщик передаёт внутрь служебной команды. Если в пароле есть **апостроф `'`**, кавычки `"`, знак `$`, обратная кавычка `` ` `` или слэш `\` — команда рвётся пополам, и ты увидишь непонятную ошибку про «SyntaxError» или «не удалось сгенерировать хэш пароля». Установка встанет, и догадаться, в чём дело, невозможно.
>
> Поэтому пароль делаем скучный и надёжный: **латинские буквы, цифры, 12+ знаков.** Например `MojGermes2026ok`. Никаких русских букв, никаких знаков препинания.
>
> Если нажмёшь просто Enter — поставится учебный пароль `Hermes_2026!`. Он известен всем, кто читал этот урок. Меняй сразу или придумай свой с самого начала.

Когда всё закончится, установщик напечатает сводку и сохранит её в файл `~/hermes-credentials.txt` на сервере. Там адреса, логин и напоминалки. Пароль оттуда никому не показывай.

Дальше установщик ещё раз сам включит автозапуск помощника («Автозапуск диспетчера (24/7, без Telegram — это отдельный модуль)») — вопросов там нет.

> **`hermes: command not found` сразу после установки?** Это не поломка. Гермес лежит в папке `~/.local/bin`, а окно терминала, открытое до установки, про эту папку ещё не знает. Лечится одним из трёх способов, от простого к сложному:
> 1. **Перезайди на сервер:** закрой окно Netcatty (или набери `exit`) и подключись заново. Это самый надёжный путь.
> 2. Пиши команду с полным путём: не `hermes`, а `~/.local/bin/hermes` — например `~/.local/bin/hermes --version`.
> 3. Выполни `source ~/.bashrc` и попробуй снова.

## Шаг 4. Подключаем бесплатный мозг (Nous Portal)

Это происходит **внутри установки**, сразу после того, как ты выбрал `Quick Setup (Nous Portal)`. Я выношу его в отдельный шаг, потому что тут человек впервые делает что-то руками в браузере.

На экране появится примерно такое:

```
Starting Hermes login via Nous Portal...
Portal: https://portal.nousresearch.com
1. Open: https://portal.nousresearch.com/manage-subscription?user_code=XXXX-XXXX
2. If prompted, enter code: XXXX-XXXX
Waiting for approval (polling every 1s)...
```

Что делаешь:

1. **Скопируй ссылку из терминала** и открой её в браузере на своём компьютере или телефоне. На сервере браузера нет — сам он открыть её не может, поэтому переносим руками.
2. Войди в свой аккаунт Nous (тот, что заводил в [шаге 0](#шаг-0-аккаунт-nous-заводим-заранее)) — например, тем же входом через Google.
3. Если страница попросит код — введи те же `XXXX-XXXX`, что в терминале.
4. Страница покажет, к какому аккаунту подключается Гермес. Нажми кнопку подключения. Появится надпись, что Гермес подключён и окно можно закрыть, — закрывай.
5. Вернись в терминал. Он сам допишет, что вход удался, и покажет список моделей.

> ⚠️ **Ссылка и код одноразовые и свои при каждом запуске.** Чужой код не подойдёт, а свой никому не давай — это вход в твой аккаунт.

**Выбор модели.** Дальше появится список. Нам нужна **бесплатная** — она помечена кружком **●** как «по умолчанию». Просто нажми Enter, и Гермес возьмёт её.

> **Почему я не пишу имя модели.** Бесплатные модели в Nous меняются: в начале октября была одна, сейчас другая, через месяц будет третья. Если я впишу имя в урок, через две недели ты будешь искать в списке то, чего там нет. Поэтому правило простое: **бери ту, что помечена как бесплатная / по умолчанию.** Захочешь сменить потом — команда `hermes model`.

**Если спросит про Tool Gateway** — покажет список галочек: веб-поиск, картинки, видео, озвучка, браузер. Отметь **веб-поиск и картинки**: на бесплатном тарифе они обычно доступны. Видео на бесплатном, скорее всего, не будет — это нормально, оно нам в уроке 0 не нужно. Экран может выглядеть иначе, чем я описываю, — его мы честно живьём не видели ([см. список](#что-мы-честно-не-проверяли)).

<!-- 📸 скриншот: экран со ссылкой и кодом входа -->
<!-- 📸 скриншот: список бесплатных моделей с кружком ● -->

> 🔴 **Главная ловушка на всю жизнь с Гермесом: мозг руками не переключай.**
>
> Если потом захочется сменить провайдера модели — **не трогай настройки руками**. Есть две правильные команды: `hermes portal` (вернуться в бесплатный Nous) и `hermes model` (выбрать модель). Всё.

> ```

> ```
> Или просто скажи Гермесу в чат: *«у меня ошибка входа в модель, проверь model.base_url и почини»*.

## Шаг 5. Свой бот в Telegram

Теперь делаем так, чтобы помощник отвечал тебе с телефона. Это пять минут на телефоне, терминал пока не нужен.

1. В Telegram найди **@BotFather** (обязательно с синей галочкой — остальные подделки) и отправь ему `/newbot`.
2. Он спросит **имя** — любое, человеческое: «Мой помощник».
3. Потом спросит **username** — он должен быть свободен и **обязательно кончаться на `bot`**: например `moy_pomoshnik_2026_bot`.
4. BotFather пришлёт **токен** — длинная строка вида `123456789:ABCdef...`. Скопируй её, она понадобится через минуту.
5. Теперь напиши боту **@userinfobot** любое слово. Он пришлёт твой **числовой ID** — что-то вроде `357912468`. Тоже скопируй.

> **Токен бота — это пароль от бота.** Не выкладывай его в чат потока, не показывай на скриншотах. Если он утёк — у BotFather есть команда `/revoke`, она выдаст новый.

**Зачем ID.** Это пропуск: помощник будет отвечать **только тебе**. Любой посторонний, который найдёт твоего бота, получит отказ. Поэтому ID должен быть именно числом, а не твоим `@username` — по username пропуск не работает.

## Шаг 7. Проверка «живой»

Ответ должен прийти **за пару секунд**.

⚠️ Критерий — **«ответил по делу»**, а не «назвал точное имя модели». Бесплатные модели иногда называют себя как придётся или уклончиво — это не поломка.

**Вторая проверка, самая убедительная.** Напиши ему:

```
Сколько свободного места на диске и сколько свободной памяти? Покажи командами.
```

Он сам выполнит нужные команды на сервере и покажет цифры. Вот это и есть разница между «чат-ботом» и «помощником»: у него есть руки.

## Шаг 7а. Запасной мозг: если бесплатную модель уберут

**Зачем.** Бесплатные модели не вечные. 27 октября 2026 года Nous без предупреждения сделал платной модель, которая ещё накануне стояла «по умолчанию». У кого не было запасной — помощник просто замолчал. Лечится заранее и **бесплатно**: даём Гермесу список запасных бесплатных моделей. Основная пропадёт — он сам пересядет на следующую по списку и продолжит отвечать.

**Как.** Терминал почти не нужен — просим самого Гермеса. Напиши ему в Telegram или в Chat:

```
Сделай резервную копию ~/.hermes/config.yaml. Потом добавь в него ключ верхнего уровня fallback_providers (НЕ внутрь model:) с тремя запасными моделями по порядку: stepfun/step-3.7-flash:free, ornith/ornith-1.5-122b:free, poolside/laguna-s-2.1:free. У каждой provider: nous и base_url: https://inference-api.nousresearch.com/v1. Покажи, что получилось, и дождись моего «да». Перезапуск шлюза не делай — я сам.
```

Посмотри, что он показал, ответь «да». Потом в Netcatty:

```
hermes gateway restart
hermes fallback list
```

Вторая команда покажет основную модель и три запасные под ней.

> ⚠️ **Тут имена моделей есть — и это исключение.** Это список бесплатных **на 27.10.2026**, он меняется. Свой актуальный смотри командой `hermes model` (там же видно, какие бесплатные) или на портале Nous. **Раз в неделю проверяй, что твоя основная модель всё ещё бесплатная.**

**Как понять, что резерв сработал.** В ответе помощника появится строчка вроде `⚠️ Model fallback: … unavailable (model not found); using stepfun/step-3.7-flash:free via nous.` Это не поломка: основная отвалилась, а помощник не замолчал. Значит, пора выбрать новую основную через `hermes model`.

<details>
<summary><b>Для тех, кто правит руками</b></summary>

В `~/.hermes/config.yaml` (и в конфиге каждого профиля, если они есть) — отдельный ключ на верхнем уровне, не внутри `model:`:

```yaml
fallback_providers:
  - provider: nous
    model: stepfun/step-3.7-flash:free
    base_url: https://inference-api.nousresearch.com/v1
  - provider: nous
    model: ornith/ornith-1.5-122b:free
    base_url: https://inference-api.nousresearch.com/v1
  - provider: nous
    model: poolside/laguna-s-2.1:free
    base_url: https://inference-api.nousresearch.com/v1
```

Порядок важен — пробуются сверху вниз. Перед правкой — копия файла, после — `hermes gateway restart`.

🔴 **Ловушка:** блок `fallback:` **внутри** `model:` Гермес не читает. С виду резерв есть, а на деле нет. Только отдельный ключ `fallback_providers`.

Если меняешь **основную** модель — проверь `hermes config get model.context_length`: число не должно быть больше, чем окно модели (у большинства бесплатных Nous — 262144). Иначе длинная переписка упадёт.

</details>

> **На потом:** все запасные сейчас у того же Nous. Если ляжет весь Nous — резерва не будет. Следующий шаг — второй провайдер (например, бесплатные модели OpenRouter), но это уже не урок 0.

## Шаг 7б. Бесплатные модели: как выбрать и как сменить

**Зачем.** В [шаге 4](#шаг-4-подключаем-бесплатный-мозг-nous-portal) ты взял бесплатную модель по умолчанию, в [шаге 7а](#шаг-7а-запасной-мозг-если-бесплатную-модель-уберут) дал ей трёх запасных. Но список бесплатных у Nous живой: модели приходят, уходят, становятся платными. Этот шаг — памятка на всю жизнь: как посмотреть, что бесплатно сейчас, и как пересадить помощника на другую модель, ничего не сломав.

Сейчас его можно не проходить. Вернёшься, когда увидишь в ответе помощника строчку `Model fallback` или когда придёт время еженедельной проверки.

> 🔴 **Модель меняем только тремя способами:** командой `hermes model`, командой `hermes fallback` или просьбой к самому Гермесу в чате. В настройки провайдера руками не лезем — почему, написано в [ловушке шага 4](#шаг-4-подключаем-бесплатный-мозг-nous-portal).

### 1. Смотрим, что стоит сейчас

В Netcatty:

```
hermes fallback list
```

Увидишь примерно такое (имена — **на 29.10.2026, они меняются**):

```
  Primary:   reflection/beam-1.0-501b-a23b:free  (via nous)

  Fallback chain (3 entries):
    1. stepfun/step-3.7-flash:free  (via nous)
    2. ornith/ornith-1.5-122b:free  (via nous)
    3. poolside/laguna-s-2.1:free  (via nous)
```

- **Primary** — основная модель, она отвечает всегда.
- **Fallback chain** — запасные, по порядку сверху вниз.
- **via nous** — модель берётся через Nous Portal.

Из Telegram то же видно без терминала — отправь боту команду:

```
/status
```

В ответе будет строка с моделью и провайдером. Это надёжнее, чем спрашивать «какая ты модель»: бесплатные модели называют себя как придётся ([шаг 7](#шаг-7-проверка-живой)).

### 2. Смотрим, какие модели бесплатные прямо сейчас

Самый честный источник — сам список в `hermes model`: Гермес каждый раз берёт его у Nous свежим.

1. В Netcatty введи `hermes model` → Enter.
2. Первый список — **провайдеры**. Стрелкой выбери **Nous Portal** → Enter. Обычно он уже стоит первым и подсвечен — это твой текущий.
3. Если попросит войти — сделай как в [шаге 4](#шаг-4-подключаем-бесплатный-мозг-nous-portal): ссылка в браузер, код, вернулся в терминал.
4. Второй список — **модели**. Вот как узнать бесплатную:
   - справа у неё написано **`free`** (или **`Free`**), а не цена в `$`;
   - в имени обычно хвост **`:free`** — например `stepfun/step-3.7-flash:free` (пример на 29.10.2026);
   - на бесплатном аккаунте платные вынесены отдельным блоком с припиской `Upgrade at … for paid models` — выбрать их нельзя;
   - курсор сразу стоит на твоей **текущей** модели.
5. Просто посмотреть и ничего не менять? Нажми **Esc** (или выбери внизу `Skip (keep current)`). Модель останется прежней.

> ⚠️ **Портал Nous в браузере.** На portal.nousresearch.com тоже есть каталог моделей, но как там помечены бесплатные, мы живьём не проверяли. Ориентируйся на `hermes model` — это ровно тот список, из которого помощник реально может выбрать.

### 3. Меняем основную модель

Каждый пункт — одно действие.

1. В Netcatty: `hermes model` → Enter.
2. Выбери **Nous Portal** → Enter.
3. В списке моделей стрелками дойди до нужной **бесплатной**. Список длинный? Начни печатать часть имени — например `step` — список сузится.
4. Нажми **Enter**.
5. Если вылезет предупреждение и вопрос `Switch anyway? [y/N]` — прочитай текст над ним. Не уверен — нажми `N` и выбери другую модель.
6. Перезапусти шлюз, чтобы Telegram подхватил новую модель:
   ```
   hermes gateway restart
   ```
7. Проверь в терминале:
   ```
   hermes fallback list
   ```
   В строке `Primary` должна стоять новая модель.
8. Проверь в Telegram: отправь боту `/status` — там тоже новая модель. Потом напиши обычное «Привет» — ответ по делу значит, что всё работает.

> **Без перезапуска шлюза** Telegram продолжит старый разговор на старой модели. Новая включится только в новой беседе. Поэтому пункт 6 не пропускай.

> 🔴 **Новая основная не должна стоять в запасных.** Если ты сделал основной модель, которая была запасной №1, — в резерве теперь дубль, и запасных по сути две. Убери её из резерва и добавь другую бесплатную (пункт 4 ниже).

### 4. Меняем список запасных

Как устроен резерв, мы разобрали в [шаге 7а](#шаг-7а-запасной-мозг-если-бесплатную-модель-уберут). Тут — как его править. Самый простой путь — попросить Гермеса в Telegram или в Chat, как в 7а: он покажет, что получилось, и дождётся твоего «да».

**Добавить запасную:**

```
Сделай резервную копию ~/.hermes/config.yaml. Добавь в конец списка fallback_providers модель ИМЯ_МОДЕЛИ с provider: nous и base_url: https://inference-api.nousresearch.com/v1. Покажи результат и дождись моего «да». Шлюз не перезапускай.
```

**Убрать запасную:**

```
Сделай резервную копию ~/.hermes/config.yaml. Убери из fallback_providers модель ИМЯ_МОДЕЛИ, остальные не трогай. Покажи результат и дождись моего «да». Шлюз не перезапускай.
```

**Переставить порядок:**

```
Сделай резервную копию ~/.hermes/config.yaml. Переставь fallback_providers в таком порядке: МОДЕЛЬ_1, МОДЕЛЬ_2, МОДЕЛЬ_3. Больше ничего не меняй. Покажи результат и дождись моего «да». Шлюз не перезапускай.
```

`ИМЯ_МОДЕЛИ` замени на точное имя из `hermes model` — целиком, вместе с хвостом `:free`.

После твоего «да» — в Netcatty:

```
hermes gateway restart
hermes fallback list
```

Во втором выводе проверь две вещи: запасные стоят в нужном порядке, и ни одна не совпадает с `Primary`.

**То же самое без чата — командами.** Если удобнее мышкой по спискам:

| Что нужно | Команда | Что будет |
|---|---|---|
| добавить запасную | `hermes fallback add` | тот же выбор, что в `hermes model`: Nous Portal → модель → Enter. Новая встаёт **в конец** списка |
| убрать запасную | `hermes fallback remove` | список запасных, стрелкой выбираешь лишнюю → Enter |
| посмотреть | `hermes fallback list` | основная и запасные по порядку |

Отдельной команды «переставить» нет. Либо проси Гермеса (текст выше), либо убери модель и добавь её заново — она встанет последней. После любой правки — `hermes gateway restart`.

> ⚠️ `hermes fallback clear` сносит **все** запасные разом. Новичку не нужна.

### 5. Если у тебя есть сотрудники (профили)

Это пригодится с [недели 1](../nedelya-1-jev-laya/README.md), когда появятся профили — Диспетчер, Секретарь и другие. **У каждого сотрудника своя модель и свой список запасных.** Сменил модель себе — у сотрудников всё осталось по-старому.

1. Узнай точное имя сотрудника:
   ```
   hermes profile list
   ```
2. Посмотри, на чём он сидит. Вместо `dispetcher` — имя из списка:
   ```
   hermes -p dispetcher fallback list
   ```
3. Смени ему основную модель — всё как в пункте 3, только с `-p имя`:
   ```
   hermes -p dispetcher model
   ```
4. Запасные ему — тоже с `-p`: `hermes -p dispetcher fallback add` / `remove`. Или попроси Гермеса, но назови файл сотрудника: `~/.hermes/profiles/dispetcher/config.yaml`.
5. Перезапусти шлюз этого сотрудника и проверь:
   ```
   hermes -p dispetcher gateway restart
   hermes -p dispetcher fallback list
   ```

> 🔴 **Без `-p имя` все команды работают с тобой самим — профилем `default`.** Самая частая путаница: человек «сменил модель Диспетчеру», а на деле сменил себе.

### 6. Когда менять: признаки и еженедельная проверка

**Менять пора, если:**

- в ответе помощника появилась строчка `⚠️ Model fallback: … unavailable …` — основная отвалилась, работает запасная ([шаг 7а](#шаг-7а-запасной-мозг-если-бесплатную-модель-уберут));
- в ответах или в журнале (`hermes logs gateway -n 50`) видно `This model is no longer free`, ошибку `404` или `model not found`;
- в `hermes model` у твоей основной модели справа уже не `free`, а цена, или она ушла в блок платных, или её нет в списке.

**Раз в неделю — две минуты:**

1. `hermes fallback list` — запиши, какие модели стоят.
2. `hermes model` → Nous Portal → найди в списке свою основную и каждую запасную. У всех справа `free`? Нажми **Esc** — всё в порядке.
3. Какая-то стала платной или пропала — основную меняй по пункту 3, запасную — по пункту 4.
4. Есть сотрудники — повтори пункт 1 для каждого с `-p имя`.

### 7. Типичные ошибки

| Симптом | Что делать |
|---|---|
| В ответах строчка `Model fallback` | Основная пропала. Выбери новую бесплатную основную (пункт 3) |
| Сменил модель, а `/status` в Telegram показывает старую | `hermes gateway restart`, потом снова `/status` |
| Нужной модели нет в списке `hermes model` | Значит, её убрали. Бери другую с пометкой `free` |
| `hermes model` пишет `requires an interactive terminal` | Запускаешь не из Netcatty. Открой Netcatty и повтори |
| После смены модели — «неверный ключ» | Это ловушка из [шага 4](#шаг-4-подключаем-бесплатный-мозг-nous-portal): `hermes config unset model.base_url` |
| `Switch anyway? [y/N]` при выборе | Предупреждение о модели. Прочитай текст над ним; не уверен — `N` и выбери другую |
| В `hermes fallback list` основная повторяется среди запасных | Убери дубль (`hermes fallback remove`) и добавь другую бесплатную |
| Сменил модель «Диспетчеру», а он отвечает по-старому | Ты забыл `-p имя` — сменил себе. Повтори с `hermes -p имя model`, потом `hermes -p имя gateway restart` |
| Короткие ответы идут, а длинная переписка вдруг падает | Окно новой модели меньше настройки. Смотри «Для технарей» ниже или попроси Гермеса: *«проверь model.context_length под мою модель»* |
| Все запасные тоже перестали отвечать | Скорее всего, лёг весь Nous. Подожди и проверь позже — второго провайдера в уроке 0 нет ([шаг 7а](#шаг-7а-запасной-мозг-если-бесплатную-модель-уберут)) |

<details>
<summary><b>Для технарей</b></summary>

- **Где лежит.** `hermes model` пишет `model.default` и `model.provider` в `~/.hermes/config.yaml`; у профиля — в `~/.hermes/profiles/<имя>/config.yaml`. Посмотреть: `hermes config get model.default`. `hermes fallback add/remove` пишет верхнеуровневый `fallback_providers`; устаревший одиночный `fallback_model` Гермес ещё читает, но при записи переносит в `fallback_providers`.
- **Как Гермес решает, что модель бесплатная.** Берёт каталог и цены у Nous Portal: бесплатная = нулевая цена и за вход, и за выход (или модель идёт по подписке). На бесплатном аккаунте платные строки уходят в блок «недоступных» над списком. Хвост `:free` — договорённость в именах, а не правило Гермеса.
- **Кэш списка.** Список моделей кэшируется на диске. Кажется устаревшим — `hermes model --refresh`: сносит кэш и тянет каталог заново, дальше обычный выбор.
- **Смена прямо в чате.** Есть `/model` в Telegram и в CLI. Без флагов он меняет модель **только для текущей беседы**; `/model имя --global` записывает в `config.yaml`. Переключает только между уже подключёнными провайдерами — новый провайдер добавляется только через `hermes model`. Смена модели посреди длинной беседы сбрасывает кэш промпта: следующий ход перечитает всю историю.
- **Когда применяется.** Telegram — в новой беседе; `hermes gateway restart` переводит все беседы разом. `hermes chat` — при следующем запуске.
- **Окно контекста.** После смены основной: `hermes config get model.context_length` — не больше окна новой модели (у большинства бесплатных Nous на 29.10.2026 — 262144).
- **Когда срабатывает резерв.** На rate-limit, 5xx, обрыв соединения и пропажу модели. После хода Гермес снова пробует основную.

Документация: `website/docs/user-guide/configuring-models.md`, `.../features/fallback-providers.md`, `.../profiles.md`, `website/docs/reference/slash-commands.md` в папке установки Гермеса.

</details>

## Шаг 8. Веб-интерфейс: твой офис из любой точки мира

Telegram — для повседневной работы. Но у Гермеса есть ещё **веб-интерфейс**: страница в браузере, где видно вкладку чата без ограничения на длину сообщения, список сотрудников, их навыки и доску задач. Вся настройка в интенсиве делается именно там.

### Почему мы возимся с доменом и шифрованием

Можно было бы просто открыть страницу по адресу сервера — и дело с концом. Но представь, что это за страница: через неё можно **выполнить на твоём сервере что угодно**, а на вкладке с ключами лежат все твои доступы.

Теперь два слова про интернет. Когда ты открываешь адрес, который начинается на `http://` без `s` — всё, что летит туда и обратно, идёт **открытым текстом**. Твой пароль, твои сообщения, твои ключи проходят через чужой Wi-Fi в кафе, через оборудование провайдера, через десяток промежуточных узлов — и каждый из них это видит. Буква `s` в `https://` и означает «зашифровано»: по дороге видно только то, что ты куда-то постучался, а не что именно ты передал.

**Домен нужен ровно для этого.** Сертификат шифрования выдаётся на имя (`agent.твой-домен.ru`), а не на номер. Нет имени — нет сертификата — нет шифрования.

А даёт тебе это вот что: **твой офис открывается из любой точки мира.** С телефона в поезде, с ноутбука в отпуске, с чужого компьютера у родителей. Не только с домашнего компьютера, не только из дома. Это ровно та свобода, за которой люди и ставят помощника на сервер, а не на свой ноутбук.

### Вариант А. Домен и https — так и надо (рекомендую)

Если на [шаге 3](#шаг-3-команда-1-ставим-гермеса) ты ответил `y` и ввёл домен, всё уже готово. Открой в браузере:

```
https://agent.твой-домен.ru
```

Логин `admin`, пароль — тот, что придумал при установке.

Не открылось — скорее всего, запись домена ещё не разошлась (это 5–30 минут) или указывает не на тот IP. Проверь запись и подожди. Установщик честно напишет `SSL не выпущен — DNS не подтверждён`, если не дождался. Повторить потом можно так:

```
certbot --nginx -d agent.твой-домен.ru
```

Пока ждёшь — работай через Telegram, урок это позволяет.

### Вариант Б. Без домена: туннель (если с доменом возиться не хочешь)

Домена нет или не хочешь с ним связываться — ничего страшного. Есть второй честный путь: **туннель**. Ты открываешь защищённую трубу от своего компьютера до сервера, и веб-интерфейс появляется как бы «у тебя на компьютере».

**Как это устроено, на пальцах.** У сервера нет экрана и браузера. Браузер — у тебя. Туннель «протягивает» страницу с сервера к тебе на компьютер.

> ⚠️ **Важно: без домена установщик веб-интерфейс сам не запускает.** Он только напечатает подсказку `ssh -L 9119:localhost:9119 root@…`. Если сразу открыть туннель — страница не откроется, а в окне туннеля побегут строки `connect failed: Connection refused`. На записи я наступил ровно на это. Поэтому делаем три шага по порядку.

**Шаг 1. Запусти веб-интерфейс на сервере.** В Netcatty, где ты уже на сервере, вставь и нажми Enter:

```
setsid nohup ~/.local/bin/hermes dashboard --port 9119 --no-open > ~/.hermes/dashboard.log 2>&1 < /dev/null & disown
```

Команда ничего не выведет — так и должно быть. Интерфейс просыпается 10–20 секунд и работает дальше, даже если закроешь окно. Путь `~/.local/bin/hermes` пишем целиком специально: сразу после установки просто `hermes` терминал может не найти.

Проверка через 20 секунд:

```
tail -2 ~/.hermes/dashboard.log
```

Должна быть строка `Hermes Web UI → http://127.0.0.1:9119`.

**Шаг 2. Проложи туннель со своего компьютера.** Открой **новое окно терминала на своём компьютере, не на сервере** — это важно. На Mac это программа **Терминал**, на Windows — **PowerShell** или командная строка (правой кнопкой по «Пуск» → Терминал). Вставь, заменив `IP_сервера` на свой адрес:

```
ssh -L 9119:localhost:9119 root@IP_сервера
```

- При первом подключении к серверу спросит `Are you sure you want to continue connecting (yes/no)?` — так бывает всегда с новым сервером. Пиши **`yes`** целиком и Enter.
- Потом спросит пароль от сервера. **Символы при вводе не видны** — ни звёздочек, ни точек. Так положено. Вставил → Enter.

**Это окно не закрывай**: пока оно открыто, работает туннель.

**Шаг 3. Открой браузер** на своём компьютере:

```
http://localhost:9119
```

Это адрес на твоём собственном компьютере, поэтому `http` здесь безопасен: шифрует сам туннель. Откроется пустой пока Гермес: чат, доска задач, настройки. Зайди в **Chat** и напиши ему что-нибудь короткое, например «Одним словом: ты живой?» — модель уже подключена и должна ответить.

<details>
<summary><b>Туннель кнопками в Netcatty, без команды</b></summary>

Шаг 2 можно сделать прямо в Netcatty. Нужно, чтобы сервер уже был сохранён там как хост (ты к нему подключался в [шаге 1](#шаг-1-заходим-на-сервер-через-netcatty)).

5. **«Адрес назначения»**: `127.0.0.1`, **«Номер порта назначения»**: `9119` → **«Продолжить»**.
6. **«Выберите SSH-сервер»**: выбери свой сервер → **«Продолжить»**.
7. **Метка**: например, `Гермес дашборд` → **«Готово»**.
8. В списке правил появится строка `Локально …:9119 -> SSH-туннель -> удалённо 127.0.0.1:9119`. Запусти правило (кнопка запуска у правила или **«Запустить все»** сверху).

Открой в браузере `http://localhost:9119`. Правило сохраняется: в следующий раз заходи в «Проброс портов» и запускай его одной кнопкой.

Названия кнопок взяты из русского перевода Netcatty — в твоей версии они могут чуть отличаться словами.

**Если не получилось**

|---|---|
| Браузер пишет «Не удаётся получить доступ к сайту» | Проверь, что окно с туннелем (шаг 2) открыто и ты ввёл пароль. Закрывал — открой заново |

### Вариант В. Просто адрес сервера с номером порта — так НЕ делаем

Ты можешь встретить в интернете совет: «открой `http://IP_сервера:9119` и всё». На записи я сначала тоже ткнулся так — не открылось. **Не делай так.** Пароль спросят, но и пароль, и всё, что ты потом увидишь и введёшь, включая вкладку с ключами, поедет по интернету открытым текстом. ## Шаг 9. Закрываем лишние двери

Последние две минуты урока, и они про безопасность.

На свежем сервере **межсетевой экран обычно выключен**. Это значит, что внутренняя страница помощника (та, что на порту 9119) может оказаться видна из интернета по открытому `http` — даже если ты честно выбрал вариант А или Б. Закроем.

> 🔴 **Сначала прочитай, потом вставляй — это важно.**
>
> Первая строка блока разрешает вход по SSH. Если включить экран **без неё**, ты отрежешь себе дорогу на свой же сервер и попадёшь туда только через «консоль» в панели хостинга. Поэтому блок вставляется **целиком и именно в этом порядке**.
>
> И на всякий случай: найди в панели своего хостинга кнопку «Консоль» / «VNC» заранее. Это твоя страховка.

**Сначала — поставить сам экран.** На некоторых хостингах сервер приходит в урезанном виде (при входе написано `This system has been minimized`), и программы `ufw` там просто нет: команды ниже ответят «command not found». Ставим одной командой — если `ufw` уже есть, она ничего не сломает:

```
apt update && apt install -y ufw
```

Теперь сам блок. Порядок не меняй: **`allow OpenSSH` — до `enable`**.

```
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw deny 9119/tcp
ufw --force enable
ufw status
```

Что мы сделали, по-человечески:

- `allow OpenSSH` — оставили открытой дверь, через которую ты заходишь сам;
- `allow 80/tcp` и `allow 443/tcp` — оставили открытым веб-интерфейс по домену и возможность обновлять сертификат;
- `deny 9119/tcp` — закрыли внутреннюю страницу от посторонних (ты сам к ней ходишь через домен или через туннель, им этот порт не нужен);
- `--force enable` — включили экран;
- `status` — показали, что получилось.

В конце ты должен увидеть `Status: active` и список разрешений. Если после этого Netcatty не отвалился — всё правильно.

### Что на самом деле делает команда установки

`install.sh hermes` из репозитория клуба — это обёртка над официальным установщиком Гермеса, которая закрывает несколько известных ям:

1. Проверяет запуск под `root` и переключает `stdin` на `/dev/tty` — иначе при `curl | bash` интерактивные вопросы проглатываются.
2. `unlock_dpkg` — останавливает `unattended-upgrades` и снимает локи, если свежий VPS сам ставит обновления.
3. `ensure_swap 4` — предлагает своп 4 ГБ (дефолт — «нет», отсюда [врезка в шаге 3](#шаг-3-команда-1-ставим-гермеса)).
4. Ставит `uv`, Python 3.11, Node.js 20 LTS — на случай, если они нужны чему-то ещё в системе.
5. Запускает официальный установщик: `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash`. Ему нужны только `git` и `curl`; остальное он приносит сам в `~/.hermes/tools/` — свой Python, свой Node, ripgrep, ffmpeg, chromium, `agent-browser`.
6. Спрашивает про провайдера модели, вызывает `hermes setup --portal` для варианта 1.
7. `hermes status`, `hermes doctor`.
8. `hermes kanban init` → демо-задача → `hermes kanban dispatch` → ожидание **ровно 6 × 8 секунд** → `hermes kanban list`.
9. Вопрос про домен, при `y` — nginx + certbot, реверс-прокси на `127.0.0.1:9119`, ожидание DNS циклами по 15 секунд.
10. `hermes gateway install --system --run-as-user root --start-now --start-on-login` — автозапуск 24/7.
11. Сводка в `~/hermes-credentials.txt` (`chmod 600`).

### Сколько это весит

| Что | Размер |
|---|---|
| `/usr/local/lib/hermes-agent` | ~2,5 ГБ (venv 870 МБ, node_modules 400 МБ, `.git` 857 МБ) |
| `~/.hermes/tools` | ~2,2 ГБ (свой Python, Node, chromium, ffmpeg) |
| кеш `~/.hermes/cache/uv` | ~1 ГБ, можно чистить потом |
| **Итого свободного места** | **минимум 10 ГБ** |

Служба `hermes-gateway.service` в работе держит около 500 МБ памяти — и это с подключёнными внешними серверами. У свежей установки меньше.

### Где что лежит

- Токен входа в Nous: `~/.hermes/auth.json` и `~/.hermes/shared/nous_auth.json`, права `600`. Профильный — `~/.hermes/profiles/<имя>/auth.json`.
- Ключи провайдеров и настройки Telegram: `~/.hermes/.env`, права `600`.
- Исполняемый файл: `~/.local/bin/hermes`.
- Служба шлюза: `hermes-gateway.service`.

### Полезные команды

```bash
hermes --version                  # версия
hermes portal                     # войти в Nous заново (= hermes setup --portal)
hermes portal info                # кто я, какой провайдер, что подключено
hermes model                      # сменить модель интерактивно
hermes config get model.base_url  # посмотреть адрес провайдера
hermes config unset model.base_url  # снести залипший адрес (ловушка «неверный ключ»)
hermes gateway status             # жив ли шлюз
hermes gateway restart            # перезапустить
hermes logs gateway -n 50         # журнал
hermes kanban list                # доска задач
hermes fallback list              # основная модель и запасные
hermes -z "вопрос"                # один вопрос, только ответ, без баннера
hermes doctor                     # самодиагностика
```

### Почему `--insecure` не поможет

У команды `hermes dashboard` по умолчанию адрес `127.0.0.1`; это установщик клуба принудительно ставит `0.0.0.0`, чтобы в него мог прийти nginx. Флаг `--insecure` с июня 2026 ничего не делает: публичная привязка **всегда** требует провайдера авторизации. То есть снять пароль с веб-интерфейса нельзя даже специально — и это правильно.

Опасность не в самой привязке к `0.0.0.0`, а в комбинации «`0.0.0.0` + выключенный межсетевой экран». Установщики делают `ufw allow`, но **не включают** `ufw` — а на свежем VPS он обычно выключен, и команда просто тихо ничего не делает. Отсюда [шаг 9](#шаг-9-закрываем-лишние-двери).

### Что в урок сознательно не попало

- Второй провайдер в резерве (например, OpenRouter) — на случай, если ляжет весь Nous. Пока все запасные из [шага 7а](#шаг-7а-запасной-мозг-если-бесплатную-модель-уберут) у одного Nous.
- Перенос входа Nous между профилями — работает ненадёжно, новичку с одним профилем не нужно.
- `hermes pairing` — коды доступа для других людей к твоему боту. В уроке 0 в пропуске только ты.
- Групповые чаты: по умолчанию бот в группе видит только обращения к себе. Чтобы видел всё — `@BotFather → Bot Settings → Group Privacy` выключить, потом удалить и заново добавить бота в группу.
